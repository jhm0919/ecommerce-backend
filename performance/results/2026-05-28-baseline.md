# 성능 테스트 결과 - Baseline

- 실행 환경: Local
- 서버: Spring Boot local
- DB: Local MySQL
- 테스트 도구: k6
- BASE_URL: `http://localhost:8080`
- 테스트 시간: 2분
- ramp-up: 30초
- 유지: 1분
- ramp-down: 30초

## 실행 명령어

### 상품 목록 조회

```powershell
k6 run -e BASE_URL=http://localhost:8080 performance/k6/product-list.js
```

### 상품 상세 조회

```powershell
k6 run `
  -e BASE_URL=http://localhost:8080 `
  -e PRODUCT_IDS=32376,32374,32373,32372,32371,32370,32369,32368,32367 `
  performance/k6/product-detail.js
```

### 비회원 주문 생성

```powershell
k6 run `
  -e BASE_URL=http://localhost:8080 `
  -e PRODUCT_ID=32376 `
  -e SKU_ID=92376 `
  performance/k6/order-create.js
```

## 해석

- 세 시나리오 모두 실패율 `0.00%`로 정상 통과했다.
- 상품 상세 조회는 p95 `8.03ms`, p99 `18.23ms`로 현재 조건에서 가장 안정적이다.
- 비회원 주문 생성은 쓰기 작업임에도 p95 `19.01ms`, p99 `34.76ms`로 현재 VU15 조건에서 안정적이다.
- 상품 목록 조회는 실패율은 없지만 p95 `342.99ms`, p99 `538.63ms`로 다른 API보다 응답 시간이 높다.
- 우선 최적화 후보는 상품 목록 조회 API이다.

## 병목 후보

- 상품 목록 조회의 페이지네이션 count query
- 상품 목록 조회의 정렬 조건
- SKU 재고 집계 쿼리
- 상품/SKU 데이터 규모 증가에 따른 인덱스 영향

## 보류 항목

- 주문 취소 부하테스트는 이번 baseline에서 제외했다.
- 이유:
  - 회원 JWT access token이 필요하다.
  - token의 `memberId`와 취소 대상 주문의 `member_id`가 일치해야 한다.
  - 주문 취소는 상태 변경 API라 한 번 실행하면 같은 주문 ID를 재사용할 수 없다.
- 후속 작업:
  - perf 전용 인증 토큰 발급 전략 수립
  - 재실행 가능한 PENDING 주문 seed 전략 수립
  - `order-cancel.js` 시나리오 재측정
